## How the repository works today

- **Composition.** `src/main.ts` loads dotenv, checks database variables, and starts Nest with raw-body capture. `src/app.module.ts` composes the database, WhatsApp, onboarding, and Meta signup modules. `src/whatsapp/whatsapp.module.ts` imports the owner assistant and injects a Cloud API client behind a token. `src/database/database.module.ts` registers entities and exports TypeORM repositories through feature wrappers. The CLI has a separate data source in `src/database/data-source.ts`.
- **Customer messages.** `POST /webhooks/whatsapp` verifies a signature and awaits the entire payload handler. `WhatsAppService` extracts text, sender, provider ID, timestamp, profile name, and receiving phone ID. `WebhookLeadCaptureService` looks up `Business.phoneNumberId`, checks for a duplicate, and resolves the sender. For customer traffic it finds or creates a tenant customer and conversation, inserts the message, touches the conversation, and returns an optional new-lead notification for the owner. The customer receives no support answer. `src/whatsapp/whatsapp-webhook.controller.ts:35`, `src/whatsapp/whatsapp.service.ts:66,132`, `src/whatsapp/webhook-lead-capture.service.ts:37`.
- **Owner commands.** An existing user matched by WhatsApp ID and business enters `AssistantService`. It uses a deterministic command parser and persisted multi-step state, then invokes CRM, follow-up, and sales services. Replies go through the connected business number on the webhook owner path. `src/assistant/assistant.service.ts:37,225`, `src/assistant/assistant-command-parser.service.ts`, `src/assistant/assistant-state.service.ts`.
- **WhatsApp registration.** A sender on an unknown number saying “hi” can enter the onboarding state machine. An active onboarding session currently intercepts traffic by sender before receiving-number routing. The flow collects profile information, creates a business and owner, and offers Meta connection or continuing with the current number. State survives through `OnboardingSessionRepository`. The “current number” flow does not provision a Cloud API connection. Logo handling captures a flag, and the production webhook parser only emits text. `src/whatsapp/whatsapp.service.ts:66,105,189`, `src/onboarding/onboarding.service.ts:296,346,460,520`, `src/onboarding/conversation-state.service.ts:26`.
- **Meta connection.** Signup builds an OAuth URL and signs a business ID and owner WhatsApp ID into state. The public callback exchanges a code, enumerates owned WABAs and phone numbers, chooses the first of each, and writes the connection to `Business`. `src/meta-embedded-signup/meta-embedded-signup.controller.ts:12`, `src/meta-embedded-signup/meta-embedded-signup.service.ts:31,140,198,388`, `src/meta-embedded-signup/embedded-signup-connection.service.ts:9`.
- **Schema.** The initial migration creates businesses, users, customers, conversations, messages, pipeline stages, follow-ups, tasks, audit logs, and notifications. The second adds connection metadata, nullable phone ID/token, unique WhatsApp user and provider message IDs, and onboarding sessions. The third adds sales and owner assistant sessions. Customer phone/WhatsApp ID uniqueness is business-scoped. Existing child foreign keys generally reference a single row ID and allow tenant mismatch where the child carries its own business ID. See `src/database/migrations/1759999999999-InitialSchema.ts:54`, `1760000000000-AddWebhookPersistence.ts:6`, and `1760000000001-AddAssistantPersistence.ts:6` in that directory.

## Prior plans and decisions

`README.md` describes the current backend more accurately than the earlier `whatsapp_read.md` baseline. `DATABASE_SETUP.md` omits the assistant migration and says development synchronization is enabled, while both code paths set it to false. `COPILOT_IMPLEMENTATION_PLAN.md` prioritizes a seller-facing CRM, reminder workers, and a daily brief without a dashboard. This V1 preserves shipped owner commands and shared records. It brings forward the prior plan’s unresolved durability, tenant, encryption, and CI work. Scheduled owner reminders, daily briefs, and new CRM commands stay in the older product backlog.

First address tenant identity, scoped database constraints, Meta asset binding, secrets, and durable intake before exposing merchant data or enabling customer automation. Dashboard, grounded answers, and learning can then build on the existing records. Bring manual takeover and send fencing online before switching on automatic replies.
