# Monitoring and alerts

The app emits structured JSON logs with correlation IDs and safe error classifications. Request logs omit URL/query/body and client IP; denied authentication/authorization responses are counted as `security.request_denied`. Do not enable proxy access logs on webhook paths. Container health checks cover API readiness (`/health/ready`), dashboard `/healthz`, and a worker heartbeat written only after Redis and PostgreSQL checks pass. Collect Docker health, host disk/memory, systemd backup timer results and app logs into a restricted CloudWatch log group with a defined retention period. AWS/CloudWatch resources are not provisioned in this repository task.

Use `deploy/operations.sql` with a read-only operator role to inspect outbox statuses, outbound status, AI status/error class, and webhook receipt state. Queries deliberately exclude customer text and credentials. Restrict query access to operational staff and audit access.

| Signal and trigger                                                                              | Severity      | Response                                                                                                                                                    |
| ----------------------------------------------------------------------------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API health fails for 3 consecutive 1-minute checks                                              | Critical      | Check container health/log classification, DB readiness, and recent release; roll back compatible image or recover dependency.                              |
| Worker unhealthy for 2 minutes                                                                  | Critical      | Inspect worker logs, Redis/DB health, restart; confirm outbox resumes from PostgreSQL.                                                                      |
| PostgreSQL unavailable for 2 checks or pool errors sustained 5 minutes                          | Critical      | Check provider status, TLS certificate, connections and grants; do not bypass TLS/RLS.                                                                      |
| Redis unavailable for 2 minutes                                                                 | High          | Restore Redis; PostgreSQL relay should recover dispatch. Do not manually replay ambiguous outbound sends.                                                   |
| Oldest pending/retry outbox item >5 minutes for 10 minutes, or failed count rises in 10 minutes | High          | Inspect safe operation type/error classification and worker health; retry only operations whose handlers are idempotent and whose external effect is known. |
| WhatsApp outbound `FAILED` or `UNCERTAIN` rises above 5 in 10 minutes                           | High          | Check Meta status/permissions and reconcile `UNCERTAIN` with provider history before any resend.                                                            |
| AI provider errors exceed 20% for 10 minutes or handoff rate doubles over baseline              | Medium        | Disable AI with `AI_RESPONSES_ENABLED=false`; retain inbox/manual operation; inspect provider and retrieval classifications.                                |
| Usage quota rejections spike above 10 in 10 minutes                                             | Medium        | Check configured tenant limits and abuse; do not raise limits automatically.                                                                                |
| Authentication denials exceed 20 in 5 minutes across the service                            | Medium        | Check aggregate denial counts and IdP health; investigate without logging credentials, request paths or contents.                                          |
| Backup timer exits nonzero or no successful backup within 26 hours                              | Critical      | Check SSM access, DB CA/role, age recipient and S3/KMS permissions; rerun after cause is fixed and verify the object.                                       |
| Root/data disk >80% warning, >90% critical                                                      | High/Critical | Inspect container logs, Docker images and volume growth; rotate/purge only disposable logs/images, never database data.                                     |
| Certificate expires within 14 days or renewal fails                                             | High          | Check DNS, inbound 80/443, Caddy data volume and ACME logs; repair renewal before expiry.                                                                   |

Use a 5–10 minute evaluation window for noisy provider and auth signals. Alert delivery, ownership and thresholds require staging configuration and are currently **BLOCKED** on AWS monitoring and an assigned on-call channel.
