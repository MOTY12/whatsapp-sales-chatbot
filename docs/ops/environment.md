# Production environment configuration

The application loads configuration centrally through `src/config/env.ts`. Production configuration fails closed when database, OIDC, WhatsApp credential encryption, Meta webhook, and other required settings are missing or invalid. Keep separate SSM SecureString namespaces for `staging`, `production`, `migration`, and `backup`. Never commit `.env.runtime` or copy real values into Compose files. `deploy/runtime-parameters.txt` and `deploy/migration-parameters.txt` list required keys; the migration list maps only migration DB credentials to the migration namespace. Render files atomically with mode 0600 using `scripts/render-ssm-env.sh`.

| Area                  | Variables / handling                                                                                                                                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Runtime               | `NODE_ENV=production`, `PORT`, `LOG_LEVEL`; use JSON structured logs and platform log rotation.                                                                                                                                                                    |
| PostgreSQL            | `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`, `DATABASE_SSL=true`, `DATABASE_SSL_REJECT_UNAUTHORIZED=true`, `DATABASE_SSL_CA`; use the TLS CA from the provider. `DATABASE_LOGGING=false`.                              |
| Redis/BullMQ          | `REDIS_HOST=redis`, `REDIS_PORT`, `REDIS_PASSWORD`, `REDIS_MAXMEMORY`, `JOBS_QUEUE_PREFIX`, `JOBS_CONCURRENCY`; Redis stays private and is not a durable source of work.                                                                                           |
| Merchant auth         | `DASHBOARD_PUBLIC_ORIGIN` is the exact browser-facing dashboard origin used for CSRF origin checks and HTTPS cookie mode; set the same value in the Next.js and NestJS environments. `OIDC_REDIRECT_URI` is the separate exact provider callback URL and must be registered with the identity provider. Production origins and callbacks use HTTPS. |
| WhatsApp/Meta         | `WHATSAPP_VERIFY_TOKEN`, `META_APP_ID`, `META_APP_SECRET`, `META_REDIRECT_URI`, `WHATSAPP_BUSINESS_CONFIG_ID`, `WHATSAPP_API_VERSION`, `META_GRAPH_BASE_URL`. Use only approved assets and preserve exact-byte signature validation.                               |
| Tenant DB roles       | `MERCHANT_DATABASE_USER/PASSWORD` and `IDENTITY_DATABASE_USER/PASSWORD` are distinct least-privilege roles, not the runtime application user.                                                                                                                      |
| Credential encryption | `WHATSAPP_CREDENTIAL_KEY_ID` and `WHATSAPP_CREDENTIAL_KEYS` JSON keyring. Add a new key ID, make it current, retain old keys while any ciphertext uses them, re-encrypt records, verify, then remove the old key. Never rotate by deleting a still-referenced key. |
| AI                    | `AI_RESPONSES_ENABLED=false` by default; `OPENAI_MODEL` and provider key only for an explicitly approved pilot. The tenant must also have an ACTIVE operator-approved pilot enrollment for its verified WhatsApp connection. Keep provider secrets out of dashboard containers and CI. |
| Usage limits          | `USAGE_DEFAULT_MONTHLY_WHATSAPP_MESSAGES`, `USAGE_DEFAULT_MONTHLY_AI_INPUT_TOKENS`, `USAGE_DEFAULT_MONTHLY_AI_OUTPUT_TOKENS`, `USAGE_DEFAULT_AI_TOKENS_PER_REQUEST`; set conservative pilot limits.                                                                |
| Deployment            | `PUBLIC_DOMAIN`, `KLEVA_RELEASE_TAG`, `KLEVA_API_ENV_FILE`, `KLEVA_WORKER_ENV_FILE`, and Redis container password in `/etc/kleva/compose.env`.                                                                                                                     |

Development may omit external OIDC/keyring credentials where code explicitly supports disabled local flows. Staging and production must use independent providers, databases, credentials, encryption keys, callback URLs, Meta assets, and data. Do not promote a staging database or secret into production. The backup service uses its separate `BACKUP_DATABASE_*`, `DATABASE_SSL_CA_FILE`, `AGE_BACKUP_RECIPIENT`, `S3_BUCKET`, `AWS_REGION`, and `DEPLOYMENT_ENV` values from `deploy/backup-parameters.txt`.
