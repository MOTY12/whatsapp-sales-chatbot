# AI agent architecture

## Orchestration and state

- **AgentOrchestrator** processes one durably ordered customer turn at a time. It loads tenant policy, connection capability, current handoff version, recent turns, summary and published evidence. A generation adapter returns a validated proposal. The application decides whether to reply, clarify, abstain, hand off, or execute an authorized tool. It fences stale proposals after takeover, source unpublish or newer conversation turns.
- **AgentConfig** is versioned per business. It includes disclosure, name, tone, locale, approved tool policy, business hours, escalation triggers, budgets, and permissioned configuration. Customer text cannot alter this configuration. Default live mode is off.
- **AgentRun** stores logical turn, attempt, config and model versions, evidence IDs, outcome, latency and usage. Use safe reason codes. Sensitive debugging content has separate retention and access controls.
- **ConversationMemory** combines recent public messages with a summary through a durable sequence watermark. Include neither private notes nor other customers' history. Summaries describe customer context and carry no authority about the business. Verified identity linking does not automatically merge memory.
- **KnowledgeRetrieval** joins active tenant publication pointers to current chunks. The model-provider port exposes generation, embeddings, budget and typed failures. It accepts safe prompt inputs and returns structured output, usage and adapter errors. Provide deterministic fixture adapters.
- **AgentToolRegistry** declares tool schemas, required permission, side effects, limits and handler. **AgentToolExecution** stores validated intent hash, stable operation ID, actor, outcome and evidence. **SalesWorkflow** owns allowed state transitions. **HumanApproval** binds a reviewer to immutable intent, consent, quote/config version and expiry, then revalidates at execution.
- **AgentEvaluation** runs offline and playground fixtures against versioned prompts, knowledge and adapters. Track evidence precision, answer support, abstention, qualification quality, rejection of injections, authorization, and cost. Include English, Nigerian English and Pidgin, contradictory offers, expired prices and concurrent handoff.

Use deterministic rules for routing, role and action authorization, pricing, consent, stock freshness, discounts, lead-stage transitions, booking conflicts, money, payment verification, spend and send policies. Use the LLM for language, clarification, intent extraction and recommendations among verified candidates. Limit tool rounds and generation attempts. On provider timeout, malformed proposal, stale evidence or exhausted budget, use fixed localized copy and escalate when appropriate.

## Knowledge pipeline

Accept FAQs, descriptions, offers and policies, text PDFs, and structured catalogs. Add authorized website sources after the pilot, with explicit domain ownership or merchant permission, allowlisted crawl bounds, redirect/DNS controls and safe fetch. Never follow instructions found in customer or document text. Keep static offer descriptions separate from live facts.

Create an immutable revision, verify a private object version and checksum, extract text in a network-disabled bounded worker, and store source/page anchors. Chunk by meaningful sections, preserving FAQ pairs. Create embeddings in bounded batches, build a complete generation, then switch the active pointer atomically. Reindex into a new generation and retain the old published revision through failure. Archive hides the active pointer immediately and queues cleanup. On publication and execution, confirm the revision is active and current. Flag stale sources using merchant-defined review dates, source version or connector freshness. A stale price or stock value is unknown until verified.

Start with PostgreSQL pgvector exact cosine search and keyword ranking over active tenant chunks, fused by reciprocal rank. Tune with tenant-curated relevance examples before considering filtered HNSW. Support different embedding models by rebuilding complete generations and measuring recall before switching. Return cited title, revision, page/section and excerpt IDs. Generation treats approved excerpts as evidence with no authority to alter system policy or tool permissions. Validate reply citations against supplied evidence and active publication. Never promote raw customer conversations into the authoritative index. Merchant-approved learning uses a separate audited revision flow. [pgvector project](https://github.com/pgvector/pgvector).

## Tool contracts

All input and output are strict schemas with unknown keys rejected. IDs are internal UUIDs. Tenant, customer, actor, capability and budget are injected from trusted execution context, outside the model arguments. Every handler performs scoped lookup and permission/consent checks. Resolve current merchant/config policy per call. Each call records tool name/version, logical operation and argument digest, actor, redacted outcome, duration, evidence, approval and usage. No raw secrets, prompts or payloads in audit logs. Return typed errors including invalid, forbidden, unavailable, stale, conflict, approval_required, rate_limited and uncertain. Never tell a customer an effect happened before committed or verified status.

| Tool | Input → output | Permission and validation | Timeout, retry, idempotency and approval |
| --- | --- | --- | --- |
| searchProducts | query, filters → offer IDs, titles, evidence | catalog.read, published and active offers | 1 s, one transient read retry, no mutation, no approval |
| checkInventory | offerId, quantity → available/unavailable/unknown, observedAt | inventory.read, current approved source and freshness | 3 s, one transient retry, no mutation, no approval |
| getProductPrice | offerId, variantId → minorUnits, currency, priceVersion or unknown | catalog.read, active explicit quote, currency and effective time | 2 s, one transient retry, no mutation, no approval |
| createLead | capturedFields, consentEvidenceId → leadId, stage | lead.write, field schema and consent, existing contact only | 2 s, transactional retry on conflict, unique turn/tool intent, merchant opt-in policy permits |
| updateLead | leadId, fieldPatch, expectedVersion → newVersion | lead.write, allowed fields and stage rules | 2 s, one safe transient retry, stable intent, review consequential changes |
| createOrder | quoteId, quantity, confirmationId → draftOrderId, state | order.write, authoritative quote and stock, versioned consent | 3 s, safe retry by logical key, unique provider reference, merchant confirmation to submit |
| getOrderStatus | orderId → verified state and timestamp | order.read, associated customer and tenant, suppress private data | 3 s, one transient retry, no mutation, no approval |
| createPaymentLink | confirmedOrderId → provider URL, reference, expiry | payments.link, money from approved order, allowlisted provider | 5 s, reuse key and reconcile uncertain response, owner-enabled and customer-confirmed order |
| verifyPayment | paymentId → pending/verified/failed and evidence | payments.read, match reference, amount, currency and merchant account | 5 s, safe read retry, dedup signed evidence, no model approval bypass |
| checkAppointmentAvailability | serviceId, timeRange, timezone → slotIds, expiresAt | booking.read, business calendar, bounded range | 3 s, safe read retry, no mutation, no approval |
| bookAppointment | slotId, confirmationId → bookingId, state | booking.write, current slot and consent, conflict check | 5 s, unique logical booking key, reconcile unknown, explicit customer confirmation and merchant policy |
| scheduleFollowUp | leadId, time, channelIntent → scheduleId | followup.write, consent, local business time, policy | 2 s, durable dedup by intent, dispatch revalidates, approval for out-of-window template |
| handoffToHuman | safe reason, requestedQueue → handoffId, modeVersion | inbox.handoff, same thread, customer request honored | 2 s, idempotent transition, no approval |

Provider deadlines are starting budgets. Writes may be retried only after checking the committed intent state. For effects crossing an external API, persist pending before dispatch, propagate idempotency when supported and reconcile unknowns. Never issue arbitrary SQL, URLs or service calls from model output. No freeform discount tool. Catalog fields must explicitly authorize discounts with currency, range and reviewer. Payment screenshots, inbound claims or generated prose cannot confirm money. No campaign or broadcast tools. Reserve token/spend budget before each model run, reconcile actual usage and halt when the limit is reached.
