## TENANT-002 discrepancy and release gate

The V1 tracker still says NOT_STARTED and describes empty auth files. HEAD adds live routes, OIDC discovery/exchange, separate identity and merchant database logins, digest-only sessions, business membership checks, permission helpers and forced RLS. The migration has legacy access policies and merchant SELECT policies on businesses and own membership. Other legacy tables have no merchant read grants. Distinct identity and merchant credentials reduce scope, but require actual role and session verification. Rollback and pooled transaction isolation also need positive acceptance evidence. [V1 tracker](../kleva-v1/progress-tracker.md) · [merchant DB](../../src/Auth/merchant-database.ts) · [SQL grants](../../src/database/merchant-access.ts).

At HEAD the auth suite has a temporary direct discovery probe in its setup. The Jest mock around `openid-client` recursively re-enters its module resolver via `createRequire`. The full suite failed with a stack overflow before reaching the 11 auth assertions. This demonstrates a test harness failure. It establishes neither a production authentication defect nor a working OIDC flow. The new tracker marks TENANT-002 **IN_PROGRESS** with an unverified implementation. No existing tracker status was overwritten. [Auth integration test](../../test/integration/auth-tenant.spec.ts) · [local IdP](../../test/integration/oidc-fixture.ts).
